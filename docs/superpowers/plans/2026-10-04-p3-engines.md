# P3 Engines Implementation Plan

**Goal:** Turn the P1/P2 data layer into answers. Deterministic engines that compose
`min(domestic, treaty)`, regulatory-consequence precedence, MLI/MFN effects, participation
exemptions and CIT into a leg-by-leg **flow** result. Every number the engines return carries
the `source_evidence` ids it was derived from, and every assumption or gap is surfaced as a
flag rather than silently filled in.

**Spec:** `docs/superpowers/specs/2026-10-04-tax-jurisdiction-recommender-design.md` §2, §3 (Factor 1), §8.

## Global constraints

- Pure, deterministic Python over the repositories; no I/O beyond the DB session; no LLM.
- `Decimal` everywhere, percent units 0–100 (same as storage). Results quantized to 3 dp.
- Core principle kept visible in the output: **domestic rate ≠ treaty cap ≠ amount withheld at
  payment ≠ final (post-relief) rate**. The WHT result exposes all four.
- Missing data never becomes a number: the engine returns `complete=False` and a
  `missing_*` flag. Conservative assumptions (e.g. top CIT bracket when no amount is given) are
  allowed only with an explicit flag.
- Migrations continue from **0013**. `ruff` + `mypy app` + `pytest` clean.

## Precedence and legal-modelling decisions

1. **Consequence precedence.** A `regulatory_consequence` of type `withholding_tax` applied by the
   *source* state to a recipient on a triggering list **replaces the domestic rate**. If a treaty
   rate also applies, the treaty cap is still applied (treaties prevail over domestic law in most
   systems, incl. France — Constitution art. 55) and the result carries an
   `interpretation_required` flag `consequence_vs_treaty`.
2. **Relief mechanism.** `at_source` / `credit` → withheld = final; `refund` → withheld = domestic
   and final = cap (cash-flow cost flagged); unknown (`NULL`) → withheld = domestic (conservative),
   flag `relief_mechanism_unknown`.
3. **Treaty in force** = `entry_into_force_date <= on_date` **and** a `treaty_rate` row valid on the
   date. A treaty with no recorded entry-into-force date is not applied (flag).
4. **Ownership threshold** on a treaty rate: if set and the holding is below it (or unknown), the
   treaty rate is not applied (flag).
5. **MLI** (`treaty.mli_application`, new): when a row is valid for the treaty, flag
   `mli_ppt` (principal purpose test — feeds the P4 substance factor) and, if a dividend
   minimum holding period is recorded and not met, do not apply an ownership-threshold dividend
   rate.
6. **MFN** (`treaty.mfn_clause`, new): never auto-applied (MFN activation is interpretive); the
   result carries an `interpretation_required` flag `mfn_clause` with the clause text.
7. **Participation exemption** (`holding_regime`): applies to DIVIDEND (and CAPITAL_GAIN when
   flagged) when min holding %, min holding period and — if the regime has a
   `min_subject_to_tax_rate` — the payer's CIT rate is ≥ that minimum. New column
   `exempt_share_pct` (France: 95 %, quote-part of 5 %; UAE: 100 %). Unknown payer CIT →
   exemption not granted + flag.
8. **Flow leakage** per 100 of gross income, legs S→H (WHT), H (CIT after exemption), H→U
   (WHT on the onward dividend, parent assumed to hold 100 % — flagged). Foreign tax credits in H
   are **not** modelled in v1 (flag `foreign_tax_credit_not_modelled`) — conservative and
   consistent across candidates. CAPITAL_GAIN flows are unsupported in v1 (flag).
