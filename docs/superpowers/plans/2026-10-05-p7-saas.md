# P7 SaaS hardening — plan

**Spec:** §8. Organisations, users, roles; sessions + API keys; metering; rate limits; audit log.

## Decisions
- **Roles** viewer < analyst < admin, on users and on API keys (a key acts with its own role).
  Viewer: read data and existing analyses. Analyst: run analyses, ask questions. Admin: users,
  keys, usage, audit. One organisation per user (the spec's `membership` table is folded into
  `user.role` until multi-org users are needed).
- **Auth**: `X-API-Key` (machines) or `Authorization: Bearer <session token>` (people). Session
  tokens are random 256-bit values stored as SHA-256; 7-day expiry; logout revokes.
  Passwords hashed with stdlib scrypt (n=2^14, r=8, p=1, 16-byte salt). Five failed logins for
  an email in 15 minutes → 429 for that email.
- **No public sign-up.** First admin via `python -m app.cli create-user`; admins create users
  with an initial password the user changes.
- **Website**: landing + read-only data pages stay public (served with a *viewer* key);
  Analyze / Ask / Account require a login; the session token lives in an httpOnly, Secure,
  SameSite=Lax cookie and is forwarded server-side.
- **Metering** (`saas.usage_event`): `analysis`, `ask`, `llm_call` (units = tokens) per org,
  user and key. Billing-ready, no Stripe (spec §11).
- **Rate limits** from the org's `saas.plan` (default plan `standard` when unset): analyses and
  questions per day and per minute, LLM calls per day. Exceeded → 429 + `Retry-After`.
  Starting values (configurable data, not code): standard = 300 analyses/day, 20/minute,
  300 LLM calls/day.
- **Audit** (`workflow.audit_event`): login ok/failed, logout, password change, user
  created/updated, key created/revoked.

## API
`POST /v1/auth/login`, `POST /v1/auth/logout`, `GET /v1/auth/me`, `POST /v1/auth/password`,
`GET|POST /v1/admin/users`, `PATCH /v1/admin/users/{id}`, `GET|POST /v1/admin/api-keys`,
`DELETE /v1/admin/api-keys/{id}`, `GET /v1/admin/usage`, `GET /v1/admin/audit`,
`GET /v1/profiles` (the org's analyses).
